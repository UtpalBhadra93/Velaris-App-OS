## Enterprise identity

**SAML single sign-on**, with the setup work taken off the administrator.
Paste one metadata URL and the entity ID, sign-in URL and certificate are read
for you. Certificates are **add-only** — a renewal is accepted alongside the
current one so a rollover is not an outage — while issuer and sign-in URL drift
is reported and never applied silently, because a changed issuer is either a
migration you planned or an attack.

Velaris can now hold **its own key pair**. Out of the box it is a passive
service provider that verifies the IdP's signature and holds no key; generating
one unlocks signed sign-in requests (ADFS requires them), **encrypted
assertions**, and **single logout**. Three decisions worth knowing:

- **Encryption is not authenticity.** Our certificate is published, so anyone
  can seal an assertion to it. An encrypted assertion nobody signed is refused
  exactly like an unsigned one.
- **RSA-1.5 key transport is refused**, not supported — it is what the classic
  attacks on encrypted XML target. Every decryption failure answers identically.
- **Single logout's signature is the whole gate.** The endpoint is public and
  names a user; unverified, it would let anyone keep a chosen person
  permanently signed out. An unknown subject answers exactly like a known one.

Sign-in requests are now tracked and `InResponseTo` is *checked* rather than
read.

**SCIM 2.0 provisioning** — Users and Groups, with the request shapes Okta and
Entra actually send, verified against real captures. A name-only PATCH is
answered rather than refused, because Entra quarantines a provisioning job on a
400 and a quarantined job also stops leaver deactivations.

## Omnichannel inbound

SMS, WhatsApp and call screen-pop over Twilio, Meta or a generic signed
webhook, sharing one conversation model with the email inbox rather than
becoming a parallel world.

Where a message lands is a four-step ladder, and the order is the design: an
open conversation for that person within its window, else a customer with
*exactly one* open case, else the endpoint's auto-create, else parked visibly.
Step two is deliberately narrow — "probably this one" is how a customer's
message lands on a stranger's case.

**STOP/START opt-out is enforced in the send path**, so it covers the SMS your
existing workflows already send and not only new channel replies, and it is
recorded in the consent ledger where a subject access request will find it.
WhatsApp's 24-hour session window is modelled, so replies outside it fail
loudly rather than silently. Call screen-pop goes to the **named agent only**;
Velaris is never in the media path.

## Bot Runner — RPA

Automation for systems that have no API, run as a sealed, disposable container
pinned by digest. Three refusals carry the feature, and each is enforced rather
than documented:

- **Nobody approves their own bot.** A definition stays draft until an admin
  who is *not* its creator approves it.
- **Unrestricted egress plus held credentials is refused at approval** — that
  combination is an exfiltration tool, not a configuration choice.
- **The container never holds write authority.** It returns an output matching
  its declared schema over a single-use, single-job token, and the *platform*
  performs the case write.

A `botTask` workflow node **enqueues and suspends** rather than blocking a
worker; attended bots produce a diff a person commits, unattended ones apply
directly. The runner is off unless enabled — it starts containers on a host,
which is an operator's choice, not a release.

## Authorization — the rebuild is finished

Phases 4 through 6 land: the access-role **name merge is retired** (naming an
access group `admin` no longer confers platform admin), 205 imperative role
checks are migrated, `has_role()` is deleted, and `is_admin` is a display flag
that implies nothing.

Role→privilege mapping now lives **in data** (`role_privileges` + a Platform
Roles tab), additive to the seed so a cold cache means "as before" and never
"nobody holds anything". The action catalogue is generated from the code's own
action list — 86 resources, up from zero — and no action is ungrantable.

A post-phase sweep found the population no phase could see: **58 routes with no
gate at all.** A detector that looks for gates cannot find their absence. All 58
are closed; anonymous reads went from 20 to 3.

## App Builder

The generated mobile app is now a project that runs, verified by extracting a
real archive, installing, type-checking and **driving it against a live server**
in a browser. It had never compiled before this release.

Sign-in is real — username, password and MFA — replacing a hand-pasted token
that expired in fifteen minutes. Tokens live in the device keystore, refresh
silently, and are **pinned to the server that issued them**: repoint the app and
the session is cleared first, so a token is never carried towards a host that
did not issue it. The server URL must be `https://` outside a local network.

## Security fixes

Named individually because each was reachable in a running deployment.

| Fix | What it was |
|---|---|
| **Unsigned webhooks accepted** | Four handlers treated a *missing* signature as verified. Proven: an anonymous, unsigned POST marked a real payment `succeeded`. |
| **SAML tenant escape** | `Destination` and `Recipient` were compared against a fixed string, so any `{tenant}` segment passed. |
| **SAML open redirect** | The relay-state check refused unsafe characters *by name*, so a tab character passed and the browser resolved the result to an external host — and `/login` signs any target it accepts, making it a link you could hand a victim. Fixed by naming the safe set instead. |
| **SAML JIT adopted local accounts by email** | A federated sign-in could take over an existing local account. Account linking is now off by default and explicit. |
| **SCIM crossed tenants** | A user with no directory row could be deactivated from another tenant. A directory row is now required. |
| **RS256 tokens silently unverified** | Three sites decoded without a public key, verifying HS256 only — websockets were dead and audit records lost their actor. |
| **GDPR erasure was incomplete** | Retention scrubbed case data but left submitter name and email *columns* behind. Nulling them alone would have re-enabled AI and warehouse sync, so anonymization is now its own refusal. |
| **Access groups never loaded for staff logins** | Lookups keyed on usernames while tokens carry a UUID. Resolved by precedence — user id, then username, then email — never a combined match, which would conflate accounts. |
| **HxSentinel's gate was near-inert** | Four of five rules read the subject case's own signals, which an open case never had. Signals are now extracted on evaluation. |
| **Bots could never return a result** | The gateway is host-networked and therefore had no DNS record on the container network. |

## Upgrade notes

- **Upgrade from:** v2.3.0
- **Migrations:** 156–163, verified on PostgreSQL, MySQL 8.4 and MariaDB 11.8.
- **No new feature flags.** Every capability here is switched on by its own
  configuration — a SAML provider row, a channel endpoint with a signing
  secret, or `VELARIS_CASE_BOT_RUNNER_ENABLED`. A manifest row on top would be a
  second switch that can disagree with the first.
- **Behavioural change:** naming an access group `admin` no longer grants
  platform admin. Check any group relying on that before upgrading.
- **Behavioural change:** routes that were unauthenticated are now gated.
  Anonymous document access in particular now requires a signed, expiring,
  single-document grant.
- **Studio browser-storage keys** moved from `helix_*` to `velaris_*`. The
  carry-over is automatic and removes the old keys; nobody is signed out.
