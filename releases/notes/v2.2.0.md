# Velaris v2.2.0 — Risk Intelligence & Voice

**Released:** 2026-07-28
**Type:** Minor release

> Adds a risk engine that recommends and never decides (HxSentinel), sovereign
> speech input across Studio, case forms and the customer portal (Voice Input),
> and two platform-wide corrections that matter most on a *fresh* install:
> case-level authorization now enforces by default, and tenant identity resolves
> to one answer whichever shape a deployment stores it in.

## HxSentinel — risk that recommends, never decides

A local risk engine over the work the platform already records. It scores a
case from ground-truth outcomes and shows **why**, then leaves the decision
with a person.

- **Ground truth first.** Outcomes are captured before anything is scored, so
  the engine is measured against reality rather than against its own opinion.
- **Rules, a verify gate, and feedback.** A flagged case can be held for
  verification; every reviewer decision feeds back as a labelled signal.
- **Similarity and oversight.** Cases resembling past bad outcomes surface for
  review with the neighbours that triggered them.
- **Signal packs** — reusable, shareable rule bundles, with SSRF-guarded
  fetching for community packs.
- **A local scoring model.** Trained and evaluated on the instance's own data;
  no case content leaves the box.
- **Disputes.** A subject can challenge a score, and the challenge is part of
  the record.

Recommendations are never verdicts: the engine cannot close, reject or
progress a case on its own.

## Voice Input — sovereign speech, everywhere

Push-to-talk dictation transcribed by **local Whisper on your own server**. The
Web Speech API was rejected during design because it ships the speaker's voice
to a browser vendor's cloud.

- **Transcribe-and-discard.** No row, no file, no object store — the clip dies
  with the request. Deliberately *not* the HxMeet recording path, which seals
  recordings on purpose.
- **A mic wherever words are typed.** The AI ask boxes across HxNexus, HxGraph,
  HxAnalytics and Case Manager, plus every free-text field on a case form.
- **Voice form-fill.** Speak the details and the local model proposes values;
  each proposal shows the words it came from, who said them, and how sure it
  is. **The extraction endpoint cannot write** — accepting fills the form, and
  the form saves the way it always did. A proposal whose quote is not in the
  transcript verbatim is dropped, because a model that invents a value almost
  always invents the evidence with it.
- **On the customer portal.** Customers can answer their own "Action needed"
  cards by speaking. This path is **off until a tenant turns it on**, shows an
  explicit consent notice before the first recording, and records that
  acknowledgement in the audit trail. Proposals are confined to the fields on
  the card in front of them.
- **Built for the phone.** The portal's installed PWA is the design case: an
  insecure origin says so instead of hiding the mic, recording stops when the
  app is backgrounded, and going offline hides the mic rather than queueing a
  recording onto the device.

Speech needs the optional `intelligence` extra. Without it the status endpoint
reports no engine and the mic renders nothing at all — an absent capability is
absent, never a dead button.

```bash
uv sync --all-packages --extra intelligence
```

Microphone access requires **https or localhost**. Browsers refuse it over
plain http on a LAN address, which is most visible when a customer opens the
portal on a phone.

## Platform corrections

- **HxGuard case enforcement now defaults to `enforce`.** It previously
  defaulted to `shadow`, in which every case-level gate is advisory — including
  the one protecting sealed recordings and transcripts. A fresh install that
  never set the variable would have served them to any authenticated user.
  Denials return **404**, not 403, so the gate is not an existence oracle. A
  deployment mid-migration can still choose `shadow` explicitly; silence no
  longer means open.
- **One canonical tenant identity.** Tenant references are stored in two
  non-comparable shapes across the platform (a UUID foreign key, and a slug
  string). Code that assumed one shape misbehaved silently on a deployment
  using the other — either denying a tenant's own cases, or reading per-tenant
  settings back as "not enabled". All comparisons now go through a single
  resolver that accepts both.
- **Microsecond timestamps on MySQL and MariaDB.** 176 insert and event
  timestamp columns moved to `DATETIME(6)`, so latest-wins ordering is
  deterministic instead of depending on which row happened to land first
  within the same second. PostgreSQL was never affected.

## Operations

- **systemd units** for engine, case-service and Studio (`deploy/systemd/`) —
  supervised restarts, journald logs that survive a restart, and start-on-boot.
  They replace the `nohup` launches in `start-velaris.sh`; run one or the
  other, never both.
- **Optional extras now survive a restart.** `uv sync` is exact by default and
  would prune a manually installed extra on the next run. `start-velaris.sh`
  and `update-velaris.sh` now detect what is present and re-request it.
- **The release manifest was behind.** `releases/manifest.sql` stopped at the
  v2.0.0 flags, so HxSentinel and Voice Input would have stayed dark on a fresh
  install even after upgrading. All seven code flags are now present, and the
  start script applies them automatically.

## Installation — a fresh box now installs itself

Rebuilding a server from scratch surfaced a set of failures that each needed a
manual step and a search through the deployment guide. Both setup scripts now
detect and offer to fix what is missing, and `--yes` accepts everything for an
unattended run.

- **Prerequisites install themselves**: Docker, the Compose plugin (named
  `docker-compose-v2` on Ubuntu, `docker-compose-plugin` in Docker's own repo),
  the Docker daemon, and Docker group membership — the last one re-executes the
  script inside the new group, so no logout is needed. Plus a Node 18+ check and
  `python3-cryptography` for the Python that ships externally-managed.
- **`setup-website.sh` asks for what it needs** — SMTP, branding, support
  address, the platform administrator and the dashboard login — and **copies**
  the JWT secret and RS256 public key straight out of the platform's `.env`, so
  the two halves cannot drift. It also offers to publish the site over HTTPS:
  certificates, both vhosts, dynamic DNS and the firewall.
- **The activation deadlock is gone.** The website creates each customer's user
  through the platform API, so a key cannot exist before the platform runs — but
  the platform refused to start without a key. A fresh install now runs
  unactivated by design and `./activate-velaris.sh` binds the key afterwards. A
  *revoked* key still blocks startup; only "never activated" is a warning.
- **A missing `uv` no longer reports as a licence failure**, and both scripts put
  `~/.local/bin` on PATH themselves.
- **nginx serving from a home directory** works: Ubuntu creates `$HOME` as
  `0750`, which made every page 404 while the log said "Permission denied".
- **systemd units are installed, enabled *and started***, and
  `start-velaris.sh` refuses to run alongside them instead of silently
  double-binding the ports.

## Registration survives a demo platform that is down

Issuing a product key no longer depends on the demo instance being reachable.
The key is generated and emailed immediately; creating the account on the demo
platform is attempted in the same request and, if that fails, queued and retried
with backoff (twelve attempts over roughly four hours). A deferred account gets
a freshly generated password and a second "your demo account is ready" email —
the password is never stored, which is why it cannot be the original one. An
email that already has an account is still refused outright, since retrying
cannot resolve a genuine conflict. Queued and failed rows are visible at
`GET /admin/provisioning`, with a retry endpoint beside it.

## Migrations

`125`–`132` (PostgreSQL): HxSentinel ground truth, rules, similarity,
oversight, signal packs and the local model (125–131); HxDBMigrate source
primary-key width (132).

MySQL / MariaDB: `0004` (HxSentinel microsecond timestamps) and `0005` (the
platform-wide `DATETIME(6)` sweep), with the baseline regenerated to match.

## Upgrading from v2.1.0

```bash
./update-velaris.sh
```

If you set `HELIX_CASE_HXGUARD_CASE_ENFORCEMENT` explicitly, your value is
respected. If you never set it, case-level authorization changes from advisory
to enforcing on this upgrade — intended, and the reason this release exists in
the shape it does.
